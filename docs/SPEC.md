# ТЗ: дашборд прогнозов временных рядов

Черновик v0.1 · 7 октября 2026

## 1. Цель и границы

Локальное Python-приложение, которое собирает опубликованные прогнозы макропоказателей от разных организаций вместе с их винтажами, показывает их на одном графике и в одной таблице с фактом и позволяет накладывать прогнозы базовых эконометрических моделей.

В первую версию (MVP) входит:

- загрузка прогнозов и исторических рядов из 3–5 источников с открытым доступом;
- хранение всех винтажей прогнозов в локальной базе;
- единый справочник показателей, сопоставляющий коды разных источников;
- интерактивный график и таблица «факт + экспертные прогнозы + модели»;
- семь бенчмарк-моделей: RW, RWD, RWS, RWDS, TS, MA, ARIMA.

В MVP не входит: платные источники (Consensus Economics, Bloomberg), парсинг PDF-отчётов, многопользовательский режим, размещение в интернете, продвинутые модели (VAR, ML), автоматическая оценка точности прогнозистов. Оценка точности запланирована на этап после MVP, и модель данных должна её допускать.

## 2. Термины

Весь проект держится на различии между датой, на которую дан прогноз, и датой, когда он опубликован. Эти понятия используются в коде и интерфейсе в одном и том же смысле.

| Термин | Значение | Пример |
| --- | --- | --- |
| Показатель (indicator) | Каноническая величина в едином справочнике проекта | Рост реального ВВП, % г/г |
| Территория (area) | Страна или агрегат, код ISO 3166 либо код агрегата | USA, EA20, WLD |
| Источник (source) | Организация, публикующая прогноз | МВФ, ОЭСР, ЕЦБ |
| Публикация (release) | Конкретный выпуск прогноза источника | WEO, октябрь 2025 |
| Винтаж (vintage) | Дата публикации выпуска; ключ версии данных | 2025-10-14 |
| Целевой период (target period) | Период, на который дано значение | 2027 год, 2026Q3 |
| Горизонт (horizon) | Расстояние от винтажа до целевого периода в шагах частоты ряда | h = 2 года |
| Факт (actual) | Наблюдаемое значение; тоже имеет винтажи из-за пересмотров статистики | ВВП за 2024 по данным на 2026-04 |
| Бенчмарк (benchmark) | Прогноз базовой модели, построенный внутри дашборда | ARIMA(1,1,0) |
| Точка отсечения (origin) | Последнее наблюдение, которое видит модель | 2025Q4 |

## 3. Пользовательские сценарии

Пользователь один — аналитик, работающий локально. Сценарии перечислены в порядке приоритета.

1. Сравнить источники. Выбрать показатель и территорию, увидеть на одном графике факт и последние прогнозы всех источников; те же числа в таблице «источник × целевой период».
2. Посмотреть эволюцию прогноза. Для одного источника вывести несколько винтажей, чтобы увидеть, как пересматривался прогноз на один и тот же период.
3. Наложить бенчмарк. Выбрать одну или несколько моделей, точку отсечения и горизонт; прогноз модели появляется на том же графике и в той же таблице.
4. Вернуться в прошлое. Задать дату «как было известно на …»: показываются только винтажи до этой даты, модели обучаются на данных до неё.
5. Обновить данные. Одной командой или кнопкой подтянуть новые выпуски; увидеть, что и когда обновилось и что упало с ошибкой.
6. Выгрузить. Сохранить текущую таблицу в CSV или Excel, график в PNG.

## 4. Источники данных

Источник берётся в проект, только если проходит четыре критерия; итоговый список утверждается по результатам этапа 1.

1. Данные отдаются машиночитаемо: API или файл по стабильной ссылке (CSV, XLSX, SDMX). PDF и HTML-таблицы не берём.
2. Доступ бесплатный; допускается бесплатный API-ключ.
3. Доступны прошлые выпуски, либо мы начинаем копить винтажи сами с момента запуска.
4. Лицензия разрешает локальное использование.

Фактические ряды с полной историей берутся отдельно: FRED/ALFRED, Евростат, ОЭСР, МВФ, Всемирный банк. Для каждого показателя назначается один эталонный источник факта, чтобы прогнозы сравнивались с одной и той же линией.

Главный риск этапа — несопоставимость определений. Источники расходятся по базе (г/г, в среднем за год, декабрь к декабрю, Q4 к Q4), по индексу цен (CPI, HICP, PCE), по составу агрегатов. Справочник показателей хранит эти атрибуты явно, а в сравнение попадают только ряды с совпадающим определением либо с пометкой о расхождении.

## 5. Модель данных

Данные хранятся в «длинном» формате: одна строка — одно значение одного ряда на один целевой период в одном винтаже. Записи никогда не перезаписываются: новый выпуск добавляет строки с новым винтажом.

| Таблица | Назначение | Ключевые поля |
| --- | --- | --- |
| `sources` | Справочник источников | `source_id`, название, URL, лицензия, тип доступа |
| `indicators` | Канонические показатели | `indicator_id`, название, единица, преобразование (уровень, % г/г, % кв/кв SAAR), база сравнения, частота |
| `areas` | Территории | `area_id`, название, тип (страна, агрегат) |
| `source_series` | Соответствие кода источника каноническому показателю | `source_id`, код ряда у источника, `indicator_id`, `area_id`, пометка о расхождении определения |
| `releases` | Выпуски | `release_id`, `source_id`, название, `vintage_date`, дата загрузки, путь к сырому файлу |
| `observations` | Значения прогнозов и факта | `release_id`, `indicator_id`, `area_id`, `target_period`, `frequency`, `value`, `kind` (forecast, actual, estimate) |
| `benchmark_runs` | Запуски моделей | `run_id`, модель, параметры, `origin`, винтаж обучающих данных, время расчёта |
| `benchmark_forecasts` | Результаты моделей | `run_id`, `target_period`, `value`, границы интервалов 80 % и 95 % |
| `ingestion_log` | Журнал загрузок | источник, время, статус, число строк, текст ошибки |

Правила:

- Уникальность в `observations`: (`release_id`, `indicator_id`, `area_id`, `target_period`). Повторная загрузка того же выпуска ничего не меняет.
- Сырые ответы API и файлы сохраняются как есть в `data/raw/<source>/<vintage>/`; база всегда пересобирается из них.
- Граница между фактом и прогнозом внутри выпуска берётся из метаданных источника, а не вычисляется по дате.
- Факт тоже версионируется. Если у источника нет винтажей факта, винтажом считается дата нашей загрузки.
- Для источников без архива мы копим винтажи сами: каждое обновление сохраняется как новый выпуск, если значения изменились.

## 6. Бенчмарк-модели

Все модели реализуют один интерфейс `fit(y) → predict(h)` и возвращают точечный прогноз и интервалы 80 % и 95 %. Обозначения: `y_T` — последнее наблюдение, `m` — сезонный период (4 для квартальных, 12 для месячных), `h` — горизонт.

| Код | Модель | Правило прогноза | Параметры |
| --- | --- | --- | --- |
| RW | Случайное блуждание | Прогноз равен `y_T` на всех горизонтах | нет |
| RWD | Случайное блуждание с дрейфом | `y_T + h·d`, где `d` — средний прирост за выборку | окно оценки дрейфа |
| RWS | Сезонное случайное блуждание | Значение того же сезона последнего года | `m` |
| RWDS | Сезонное случайное блуждание с дрейфом | Значение того же сезона плюс средний годовой прирост, умноженный на число лет вперёд | `m`, окно оценки |
| TS | Тренд-стационарная модель | Линейный тренд по МНК; для сезонных рядов добавляются сезонные дамми | степень тренда, сезонность |
| MA | Скользящее среднее | Среднее последних `q` наблюдений на всех горизонтах | `q` |
| ARIMA | ARIMA(p,d,q)(P,D,Q) | Автоподбор порядка по AICc либо порядок, заданный вручную | порядок, сезонность |

Определения RWDS, TS и MA подтверждены заказчиком 7 октября 2026; MA — скользящее среднее.

Общие правила:

- Модель обучается на ряде в исходной частоте и в уровнях (или логарифмах — опция). Результат переводится в единицу и частоту показателя тем же преобразованием, которым определён показатель. Пример: квартальный уровень ВВП → прогноз уровней → среднегодовой рост, сравнимый с цифрой МВФ.
- Обучение идёт на данных до точки отсечения. В режиме «как было известно на дату» используется винтаж факта на эту дату, а не сегодняшний пересмотренный ряд.
- Минимальная длина ряда: 2·`m` наблюдений для сезонных моделей, 30 для ARIMA. При нехватке модель возвращает понятный отказ, а не число.
- Результаты кэшируются в `benchmark_runs` по ключу (модель, параметры, ряд, точка отсечения, винтаж).
- На каждую модель есть тест на синтетическом ряде с известным ответом и сверка с эталонной реализацией (statsmodels или statsforecast).

## 7. Архитектура и стек

Зависимости идут в одну сторону: загрузка → хранилище → расчётное ядро → API → интерфейс. Ядро не знает об интерфейсе, поэтому фронтенд можно заменить, не трогая данные и модели.

| Слой | Что делает | Технологии (предложение) |
| --- | --- | --- |
| Загрузка (`ingest`) | Один коннектор на источник: скачать, сохранить сырой файл, разобрать, привести к общей схеме | httpx, pydantic, tenacity |
| Хранилище (`store`) | Локальная база, миграции, запросы «последний винтаж», «на дату» | DuckDB (один файл), SQL-миграции |
| Ядро (`core`) | Справочник показателей, преобразования частот и единиц, бенчмарк-модели | pandas, statsmodels, statsforecast |
| API (`api`) | Отдаёт данные и запускает модели для интерфейса | FastAPI |
| Интерфейс (`web`) | График, таблица, фильтры | Решается на этапе 4: React + Plotly/ECharts либо Dash |
| Командная строка (`cli`) | `ingest`, `status`, `serve` | Typer |

Окружение: Python 3.12, менеджер зависимостей uv, проверка кода ruff, тесты pytest. Запуск одной командой после `uv sync`. Ключи API хранятся в `.env`, файл в git не попадает.

```
forecast-dashboard/
  CLAUDE.md              # краткие правила для Claude Code
  docs/SPEC.md           # это ТЗ
  docs/sources/          # по одному файлу-паспорту на источник
  config/indicators.yaml # справочник показателей и соответствий
  src/fdash/
    ingest/              # base.py + по модулю на источник
    store/               # схема, миграции, запросы
    core/                # преобразования, models/
    api/
    cli.py
  web/                   # фронтенд
  data/raw/              # сырые файлы, не в git
  data/fdash.duckdb      # база, не в git
  tests/
```

Коннектор источника — класс с тремя методами: `list_releases()`, `fetch(release)`, `parse(raw) → строки общей схемы`. Добавление источника не требует изменений в остальных слоях.

## 8. Интерфейс

Один основной экран: слева фильтры, по центру график, под ним таблица с теми же данными. Цвета, шрифты и расположение окон берутся из существующего прототипа заказчика; здесь зафиксировано только поведение.

Фильтры:

- показатель и территория (поиск по справочнику; показывается число источников, покрывающих пару);
- источники (множественный выбор);
- винтажи: «последний у каждого источника», «на дату», либо ручной выбор нескольких выпусков;
- бенчмарк-модели, их параметры, точка отсечения, горизонт;
- период отображения.

График:

- факт — сплошная линия; прогнозы — линии от точки своего винтажа, цвет закреплён за источником;
- несколько винтажей одного источника — оттенки одного цвета, от старого к новому;
- бенчмарки — пунктир, интервалы — полупрозрачная заливка, отключаемая;
- при наведении: источник, выпуск, дата винтажа, целевой период, значение, единица;
- легенда включает и выключает ряды.

Таблица:

- строки — источник и выпуск либо модель; столбцы — целевые периоды; первая строка — факт;
- переключатель «значения / отклонение от факта / отклонение от выбранного ряда»;
- сортировка, экспорт в CSV и XLSX.

Служебные экраны: каталог показателей с покрытием по источникам; состояние данных с датой последнего выпуска каждого источника и журналом загрузок.

## 9. Нефункциональные требования

- Воспроизводимость: база полностью пересобирается из `data/raw/` одной командой.
- Идемпотентность: повторный запуск загрузки не создаёт дублей.
- Устойчивость: сбой одного источника не останавливает остальные; ошибка пишется в `ingestion_log` и видна в интерфейсе.
- Вежливость к API: соблюдение лимитов, повторы с паузой, кэш; ни один источник не опрашивается чаще раза в сутки без явной команды.
- Скорость: смена фильтра перерисовывает график быстрее 1 секунды на данных из базы; расчёт одной модели на ряде до 1000 точек — быстрее 3 секунд.
- Тесты: каждый коннектор проверяется на сохранённом образце ответа без обращения в сеть; каждая модель — на синтетическом ряде.
- Платформа: Windows, macOS, Linux; никаких внешних сервисов и Docker для запуска не требуется.
- Язык: код, имена и комментарии — на английском; интерфейс на русском; все тексты интерфейса сразу выносятся в словарь, английская версия и переключатель добавляются после MVP.

Решения заказчика от 7 октября 2026:

- Частота любая; критерий — пересечение источников.

- Глубина архива: 5 лет для годовых прогнозов, около 2 лет для остальных частот.
- Источники с бесплатным ключом допустимы.
- Основной язык — русский; переключатель языков второстепенен.

## 12. Правила для Claude Code

Этот раздел в сокращённом виде переносится в `CLAUDE.md` в корне репозитория; полное ТЗ лежит в `docs/SPEC.md`.

- Работать по этапам раздела 10. Не начинать следующий этап без подтверждения заказчика.
- Перед кодом коннектора — паспорт источника в `docs/sources/<source>.md`: адреса, параметры, пример ответа, лимиты, как устроены винтажи, лицензия.
- Ничего не утверждать об API по памяти: каждый адрес и формат проверяется реальным запросом, образец ответа сохраняется в `tests/fixtures/`.
- Не подставлять выдуманные или синтетические данные вместо реальных. Если источник недоступен — остановиться и сообщить.
- Не сопоставлять ряды разных источников без проверки определения; сомнительные случаи выносить заказчику списком.
- Любое изменение схемы базы — отдельной миграцией и с обновлением раздела 5.
- Каждая задача завершается зелёными `ruff` и `pytest` и короткой записью в `docs/CHANGELOG.md`.
- Секреты только в `.env`; `data/` и `.env` включены в `.gitignore`.
- При расхождении кода и ТЗ — сначала предложить правку ТЗ, затем менять код.
