# Разбор прототипа `forecast-testing`

Этап 0 (раздел 10 ТЗ). Дата разбора: 7 октября 2026. Прототип изучен по исходному коду. Вживую его не запускали, поэтому внешний вид восстановлен по CSS и компонентам.

## 1. Что представляет собой прототип

| | |
| --- | --- |
| Бэкенд | Python 3.11, FastAPI 0.141, pandas 3.0, NumPy 2.4, statsmodels 0.15, openpyxl. Зависимости — в `requirements.txt` и `.venv` |
| Фронтенд | React 19, TypeScript 6, Vite 8, Recharts 3.10. Сторонних UI-библиотек нет, вся вёрстка написана вручную в `App.css` |

## 2. Как устроены график и таблица

**График**: Recharts `ComposedChart` высотой 520 px.

- Факт — сплошная линия `#62b4dc` толщиной 3 px.
- Месячный прогноз — пунктир `7 5` толщиной 2,5 px, точки r = 3 с белой заливкой.
- Годовой прогноз на месячной шкале — ромб в середине года (1 июля), без интерполяции.
- Интервалы прогнозов (у макроопроса — 10–90-й перцентили) — заливка цветом ряда с прозрачностью 0,10.
- Модели — пунктир `3 4` толщиной 2,5 px; интервал 95 % — заливка с прозрачностью 0,08; отключается одним флажком вместе с интервалами прогнозов.
- Сетка — только горизонтальная, `#dfe5eb`. Подписи осей — 12 px, `#65717f`.
- Снизу `Brush` для выбора периода, обводка `#62b4dc`.
- Подсказка своя: период и затем строки «цвет · источник · выпуск · значение».
- Легенда стандартная, вкл/выкл рядов по клику нет. Кнопка «↓ PNG» сохраняет SVG графика как PNG в масштабе ×2.

**Цвета рядов** назначаются по порядковому номеру выпуска из палитры 12 цветов, а не по источнику. Девять выпусков EIA получают девять разных цветов, и после 12 выпусков цвета повторяются.

**Таблица**: строки — периоды (последние 48), столбцы — «Факт», затем каждый выбранный выпуск и каждая модель. Первый столбец и шапка закреплены, пустое значение показано как «—». Сортировки, переключателя отклонений и XLSX нет. CSV выгружается с сервера, разделитель `;`, с BOM для Excel.

**Левая панель** (360 px): блок «Источники и винтажи» — флажок на каждый выпуск с цветной меткой и датой среза. Блок «Базовая модель»:
- выбор модели с пояснением, почему она недоступна;
- точка отсечения (срез факта) и горизонт;
- кнопка «Построить на графике»;
- список построенных моделей с крестиком для удаления.

### Шрифт

```
font-family: Inter, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
```

Inter в прототип не подключён (нет `@font-face` и ссылки на Google Fonts) и на этом компьютере не установлен. Фактически прототип рисуется **Helvetica** на macOS и **Segoe UI** на Windows. ## 5. Что не переносим и почему

| Что | Почему |
| --- | --- |
| Хранилище в одном JSON и перезапись `brent_monthly.csv` при каждом старте | Противоречит модели данных: записи не перезаписываются, база пересобирается из сырых файлов. Заменяется на DuckDB и `data/raw/` |
| Фактические значения по России 2021–2025, набранные вручную в `CBR_ACTUALS` | Значения не воспроизводятся из сырого файла, проверить их происхождение нельзя. Факт нужно загружать коннектором из официального источника (Росстат, Банк России). Источник выбираем на этапе 2 |
| Справочник показателей в коде (`INDICATORS`) и связь через `platform_series_id` | Переходит в `config/indicators.yaml` с явными полями определения: показатель, единица, база, территория, частота |
| Списки выпусков и даты публикации, вписанные вручную (`EIA_RELEASES`, `published_at` у Банка России — только для одного опроса, у второго `None`) | Винтаж — ключевое поле модели. Коннектор должен находить выпуски сам (`list_releases()`), а дату публикации брать из источника |
| Граница факт/прогноз у Банка Англии, вписанная числом (`<= 2025`) | Через год станет неверной. Граница должна браться из файла или из даты выпуска |
| Сетевой код на `urllib` без повторов | По ТЗ используем httpx и tenacity |
| Цвет по номеру выпуска | По ТЗ цвет закреплён за источником, винтажи — оттенки этого цвета от старого к новому |
| Таблица «периоды × ряды», только последние 48 периодов | По ТЗ строки — источник/выпуск или модель, столбцы — целевые периоды, первая строка — факт; плюс режимы отклонений, сортировка, XLSX |
| Главная страница-витрина (крупный заголовок, схема-иллюстрация, карточки, «как это работает») | В ТЗ один основной экран и служебные экраны. Витрину заменяет каталог показателей с покрытием по источникам; стиль карточек сохраняем |
| Статический реестр источников во фронтенде (`forecastSources.ts`), включая МВФ, OBR и ЕЦБ SPF со статусами вручную | Заменяется экраном «Состояние данных» по ТЗ: данные из базы, дата последнего выпуска, журнал загрузок |
| Неработающие пункты шапки портала («О проекте», «Озеро данных», «Статистика»), иконка профиля | Заглушки без функций. Шапку предлагаю оставить визуально, но без мёртвых пунктов (см. вопрос 3) |
| Строки интерфейса прямо в разметке | По CLAUDE.md все тексты интерфейса — через словарь |
| Тесты на `unittest`, привязанные к живому JSON (`len(sources) == 4`) | Переходим на pytest с образцами ответов в `tests/fixtures/` |

## 7. Предлагаемый фронтенд-стек

**React 19 + TypeScript + Vite + Recharts**, то есть стек прототипа. Отдельный пакет `web/`, сборка отдаётся через FastAPI, чтобы запускать всё одной командой `fdash serve`.

Почему так:

1. **Дизайн нужно повторить точно.** Готовые компоненты и `App.css` переносятся почти как есть. При переходе на Dash всю вёрстку пришлось бы собирать заново в другой модели компонентов. При переходе на Plotly или ECharts пришлось бы заново подгонять вид графика: оси, подсказку, легенду, ромбы годовых точек.
2. **Recharts закрывает требования раздела 8 ТЗ:**
   - заливка интервалов (`Area` с парой значений) и пунктиры уже работают;
   - собственная подсказка уже есть, в неё добавим дату винтажа;
   - выбор периода — `Brush`;
   - вкл/выкл через легенду — около двадцати строк кода.
3. **Объём данных небольшой.** Это сотни–тысячи точек на экран, ускорение на canvas, ради которого обычно берут ECharts, не нужно.
4. **Ядро от интерфейса отделено** (раздел 7 ТЗ). Если Recharts упрётся в ограничения, заменим только компонент графика.

Дополнительно:

- **Таблица** — своя, на основе компонента прототипа. Сортировку сделаем сами, для 10–30 строк отдельная библиотека не нужна.
- **Экспорт** — CSV и XLSX формирует сервер (openpyxl), как сейчас CSV.
- **Словарь интерфейса** — простой `ru.ts` с ключами, без i18next до появления английского.
- **Шрифт** — по итогам открытого вопроса А.

Альтернативы, которые я не рекомендую:

- **ECharts.** Встроенные легенда, масштабирование и экспорт, быстрая отрисовка. Но рисунок пришлось бы подгонять под прототип, а полосы интервалов в ECharts делаются обходным путём через сложенные области.
- **Plotly.** Всё встроено, но тяжёлая сборка (несколько МБ), и его фирменный вид труднее привести к стилю прототипа.
- **Dash.** Один язык, но потребовал бы переписать весь интерфейс и хуже подходит для точного повторения дизайна.

Раздел 7 ТЗ сейчас называет варианты «React + Plotly/ECharts либо Dash». Если рекомендация принимается, нужна правка ТЗ (см. раздел 8).
