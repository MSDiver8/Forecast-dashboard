# Forecast Dashboard

Локальное Python-приложение: собирает опубликованные прогнозы показателей от разных организаций вместе с винтажами, показывает их на одном графике и в одной таблице с фактом и добавляет прогнозы бенчмарк-моделей (RW, RWD, RWS, RWDS, TS, MA, ARIMA).

Полное ТЗ — `docs/SPEC.md`. Это основной документ проекта. Целиком не загружай: перед каждым этапом читай нужные разделы. Правки в ТЗ вноси только после согласования с заказчиком.

## Текущий этап

Собран MVP (решение заказчика 7 октября 2026 — делать MVP целиком и показать): группы A, B, C загружены частично, группа F отложена. Список открытых вопросов — в последнем отчёте заказчику и `docs/CHANGELOG.md`. Этапы и критерии приёмки — раздел 10 ТЗ.

## Принятые решения

- Группы показателей MVP (раздел 4.1 ТЗ):
  - A. Россия, годовые: среднесрочный прогноз Банка России, макроопрос Банка России, МВФ WEO.
  - B. Мир, годовые: МВФ WEO, ОЭСР Economic Outlook, ЕЦБ.
  - C. Нефть Brent: EIA STEO, ЕЦБ SPF, ЕЦБ MPD, Всемирный банк CMO, опрос Нацбанка Казахстана, Банк Англии MPR (предпосылка на основе фьючерсов, не собственный прогноз).
  - F. Зерновые рынки: USDA WASDE, IGC, FAO-AMIS.
- Сравниваются только ряды с одинаковым определением: показатель, единица, база сравнения, территория. Адаптеры между определениями не пишем.
- Глубина архива винтажей: 5 лет для годовых прогнозов, около 2 лет для остальных частот.
- Источники с бесплатным API-ключом допустимы (FRED, EIA). Ключи только в `.env`.
- Сравнение по винтажам, включая ретроспективное («как было известно на дату»), входит в MVP.
- MA — скользящее среднее последних q наблюдений.
- Интерфейс на русском; все тексты интерфейса через словарь, английский язык — после MVP.
- Факт загружается только программой из официального источника. Ручной ввод фактических значений запрещён.
- Эталон факта Brent — FRED `MCOILBRENTEU`; история из выпусков EIA STEO — факт на дату выпуска для ретроспективного режима.
- Расположение панелей — из прототипа заказчика. Визуальный стиль (цвета, шрифты, шапка НЦСЭД) — как на платформе data.iep.ru. Значения — в `docs/prototype-review.md`.
- Шрифты как на платформе: Circe, меню — Fira Sans Condensed. Файлы Circe в репозиторий не кладём: лицензия коммерческая.
- График: факт — сплошная толстая линия, прогнозы — сплошные линии, бенчмарки — пунктир.

## Стек

Python 3.12, uv, ruff, pytest, DuckDB, pandas, statsmodels, statsforecast, httpx, pydantic, tenacity, FastAPI, Typer. Фронтенд: React, TypeScript, Vite, Recharts.

## Команды

- `uv sync` — установить зависимости
- `uv run pytest` — тесты
- `uv run ruff check . && uv run ruff format .` — проверка и форматирование
- `uv run fdash ingest --all`, `uv run fdash status`, `uv run fdash rebuild`, `uv run fdash serve` (порт 8100)
- `cd web && npm run build` — собрать интерфейс
- На этой машине проект в iCloud: перед `uv` задавать `UV_PROJECT_ENVIRONMENT=$HOME/.local/share/fdash/venv` (см. README)

## Модель данных

- «Длинный» формат: одна строка `observations` — одно значение одного ряда на один целевой период в одном выпуске. Ключ уникальности: (`release_id`, `indicator_id`, `area_id`, `target_period`).
- Винтаж — дата публикации выпуска. Записи не перезаписываются: новый выпуск добавляет строки.
- Сырые файлы сохраняются в `data/raw/<source>/<vintage>/`; база полностью пересобирается из них.
- Коннектор источника — класс с методами `list_releases()`, `fetch(release)`, `parse(raw)`.

## Правила работы

- Работай по этапам раздела 10 ТЗ. Следующий этап не начинай без подтверждения заказчика.
- В начале каждого этапа составь план и согласуй его, код пиши после согласования.
- Перед кодом коннектора напиши паспорт источника в `docs/sources/<source>.md`: адреса, параметры, пример ответа, лимиты, устройство винтажей, лицензия.
- Ничего не утверждай об API по памяти. Каждый адрес и формат проверяй реальным запросом и сохраняй образец ответа в `tests/fixtures/`.
- Не подставляй выдуманные или синтетические данные вместо реальных. Источник недоступен — остановись и сообщи.
- Не сопоставляй ряды разных источников без проверки определения. Сомнительные случаи выноси заказчику списком.
- Изменение схемы базы — отдельной миграцией и с правкой раздела 5 ТЗ.
- Задача завершена, когда `ruff` и `pytest` проходят, а в `docs/CHANGELOG.md` есть короткая запись.
- `data/` и `.env` в `.gitignore`.
- Код расходится с ТЗ — сначала предложи правку ТЗ, потом меняй код.
- Код, имена и комментарии в коде — на английском. Общение с заказчиком и документация — на русском.
